# 内容规范（词条 / 事件 / 物品 / 结局 / 成就）

所有内容都是**纯数据**（可 JSON 序列化的普通对象数组），放在 `src/common/core/content/` 下，
由 `content/index.js` 的 `buildContent()` 汇总成 5 个池，`app.ux` 装配一次后交给
`engine.js` 消费（页面不直接 import 内容，否则每页字节码都会内联一份，手环会内存耗尽重启）。
写完请跑：

```bash
node tools/validate-content.mjs      # 结构校验（必须 0 错误）
```

## 通用约定

- `id` 全局唯一，前缀区分类型：`T`天赋 `E`人生事件 `C`修仙事件 `I`物品 `D`结局 `A`成就
- 中文文案不要用引号/换行；单条 `text` ≤ 60 字（手环屏幕放不下更多）
- `rarity`：1 凡品 / 2 灵品 / 3 仙品 / 4 神品
- 数值要克制：属性普遍在 0~30 之间，别出现 +50 这种

## 1. 天赋词条 `content/talents.js` → `export const TALENTS = [...]`

```js
{
  id: 'T001',
  name: '过目不忘',        // ≤6 字
  rarity: 2,
  tag: '智慧',             // 智慧/体质/社交/幸运/修仙/诡异
  desc: '看一遍就记住，考试从不复习',   // ≤16 字
  eff: { iq: 2, luck: 1 }
}
```

`eff` 可用的键：

| 键 | 含义 |
|---|---|
| `iq` `eq` `hp` `luck` | 属性加成（可负） |
| `lifespan` | 寿元（年） |
| `progressRate` | 修为增速加成，如 `0.5` = +50% |
| `breakthrough` | 突破成功率加成，如 `0.1` |
| `luckRate` | 好事权重加成，如 `0.3` |
| `flag` | 打一个标记（字符串），供事件 `req.flags` 判断 |
| `item` | 直接给一件物品的 id |
| `spiritRoot` | `'single'/'dual'/'triple'/'pseudo'/'heaven'`：直接开启修仙 |
| `forbidCultivation` | `true`：此生无法修仙（用于"诡异"类词条） |
| `daoHeart` | 初始道心 |
| `dieChance` | 出生即死的概率（很小，如 0.02） |

**要求：至少 120 条**，稀有度分布大致 凡品 45% / 灵品 32% / 仙品 18% / 神品 5%；
修仙相关（`tag: '修仙'` 或带 `spiritRoot`/`progressRate`）不少于 25 条。

## 2. 人生事件 `content/events_life.js` → `export const EVENTS_LIFE = [...]`

```js
{
  id: 'E001',
  title: '少年得志',        // ≤6 字
  text: '你在数学竞赛中一举夺魁，全校都知道了你的名字。',   // ≤60 字
  age: [9, 15],            // 年龄区间，闭区间，必填
  weight: 10,              // 相对权重，正整数（常见 5~20，稀有 1~3）
  kind: 'life',            // life 普通 / item 获得物品 / danger 危险
  once: true,              // 可选，**默认 true**（一生只触发一次）；写成 false 表示可反复触发（如"闭关""平淡"这类日常）
  req: { iq: 8, flags: ['x'], lt: { eq: 5 } },   // 可选，见下
  eff: { iq: 1, luck: 1 }
}
```

`req`（全部满足才可能触发，均可省略）：
`iq/eq/hp/luck`（≥）、`lt: {iq: 12}`（<）、`flags[]`、`notFlags[]`、`items[]`、`talents[]`、
`ageMin`、以及**体系条件**：

| 键 | 含义 |
|---|---|
| `path: 'body'` | 走在某条体系上（`cultivate` 修仙 / `body` 炼体 / `magic` 魔法 / `tech` 科技） |
| `pathLevel: 5` | 该体系境界下标 ≥ 5（配合 `path` 用） |
| `noPath: true` | 还没踏入任何体系 |
| `dualPath: true` | 已有"双修"资质 |
| `cultivation: true` | ↑ 旧写法，等价于 `path: 'cultivate'`（保留兼容） |
| `noCultivation: true` | 没有修仙 |
| `realm: n` | ↑ 旧写法，等价于修仙的 `pathLevel` |

`eff` 在天赋那套基础上额外支持：

| 键 | 含义 |
|---|---|
| `progress` | 当前体系的资源 +n（修为/气血/魔力/知识） |
| `sp` / `daoHeart` | 特殊属性 +n（道心/铁骨/灵性/严谨，作用于主修） |
| `pathUp: true` | 立刻尝试突破当前体系（旧写法 `realmUp` 等价） |
| `tribulation: true` | 触发当前体系的劫难（天劫/雷劫淬体/元素暴动/学术刁难） |
| `enterPath: 'body'` | 踏入某条体系（修仙旧写法 `spiritRoot` 等价） |
| `dualPath: true` | 给予"可同时走两条体系"的资质（一般写在天赋里） |
| `die: '死因文字'` | 立刻死亡 |
| `dieChance: 0.2` | 概率死亡 |

## 3.5 体系内容包（`content/path_*.js`）

每条体系一个文件，导出 5 个数组；id 段互不重叠：

| 体系 | 文件 | 事件 | 词条 | 物品 | 结局 | 成就 |
|---|---|---|---|---|---|---|
| 修仙 | `path_cultivate2.js` | `C151+` | `TC` | `IC` | `DC` | `AC` |
| 炼体 | `path_body.js` | `B001+` | `TB` | `IB` | `DB` | `AB` |
| 魔法 | `path_magic.js` | `M001+` | `TM` | `IM` | `DM` | `AM` |
| 科技 | `path_tech.js` | `H001+` | `TH` | `IH` | `DH` | `AH` |

规则：除"入门/觉醒"类（≤6 条、`weight` ≤3、带 `eff.enterPath`）外，**每条事件都必须带
`req: { path: '<体系>' }`**，否则没走这条体系的人也会抽到。

**要求：至少 260 条**，覆盖这些年龄段：
`0-3 婴幼儿`、`4-6 学前`、`7-12 小学`、`13-18 中学`、`19-25 大学/初入社会`、
`26-40 事业家庭`、`41-60 中年`、`61-80 老年`、`80+ 余晖`。
每个年龄段不少于 25 条；其中"好事/坏事/中性"大致 1:1:1；要有生活气息、有梗但不低俗。

## 3. 修仙事件 `content/events_cultivation.js` → `export const EVENTS_CULTIVATION = [...]`

同上的结构，但 `kind: 'cultivate'`。除少数"机缘启蒙"外，**都要带 `req: { cultivation: true }`**
（或 `realm: n`）以免没修仙的人抽到。内容要覆盖：

- **觉醒与入门**（灵根测试、被仙门看中、偶得残卷）— 少数允许 `req: {}`，但要 `weight: 1~2`
- **修炼日常**（闭关、顿悟、灵气潮汐、心魔、道友切磋）
- **秘境与机缘**（上古洞府、灵药园、传承、夺宝、被围杀）
- **妖兽与强敌**（斗法、受伤、以弱胜强）
- **炼丹炼器**（炸炉、成丹、法宝出世）
- **突破与天劫**（`realmUp: true` / `tribulation: true`）
- **仙门与人情**（拜师、同门、道侣、叛门）
- **高阶专属**（`realm: 8+` 的元婴/化神以上事件）

**要求：至少 130 条**，`weight` 与 `eff` 的收益要随境界递增（低境界给 `progress: 5~20`，
高境界给 `progress: 60~200`）。

## 4. 物品 `content/items.js` → `export const ITEMS = [...]`

```js
{ id: 'I001', name: '青锋剑', kind: '法宝', rarity: 2, desc: '吹毛断发，剑身泛着幽蓝',
  eff: { hp: 1, breakthrough: 0.03 } }
```
`kind` 取 `'法宝' / '丹药' / '灵物' / '功法'`。**要求：至少 80 件**，
`eff` 与稀有度匹配（神品可以给 `lifespan: 200`、`progressRate: 1` 这种）。

## 5. 结局 `content/endings.js` → `export const ENDINGS = [...]`

```js
{ id: 'D001', name: '寿终正寝', rank: 2, desc: '儿孙绕膝，你安然闭上眼。',
  req: { luck: 8 }, ageMax: 120 }
```
`rank` 1~5（对应 平凡/优秀/稀有/史诗/传说），引擎会挑满足条件里 rank 最高的。
**要求：至少 60 个**，要覆盖：早夭 / 意外 / 平凡一生 / 富贵 / 名留青史 / 各种修仙结局
（走火入魔、殒于天劫、兵解、飞升、证道……）/ 诡异结局。带 `req.realm` 的要有梯度。

## 6. 成就 `content/achievements.js` → `export const ACHIEVEMENTS = [...]`

```js
{ id: 'A001', name: '长命百岁', desc: '活到一百岁', req: { ageMin: 100 } }
```
`req` 同上（支持 `realm`、`ageMin`、属性、flags、items、talents）。
**要求：至少 50 条**，覆盖：年龄里程碑、属性极端值、境界里程碑、收集类（items/talents）、
奇葩死法（用 `flags` 配合事件里的 `flag`）。
